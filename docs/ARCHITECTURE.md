# AutoSkill 架构文档

## 1. 四层架构

```
┌────────────────────────────────────────────────────────────┐
│ 接入层  FastAPI(/ensure /call /agent/chat) + CLI + Agent   │
├────────────────────────────────────────────────────────────┤
│ 调度层  Router(向量召回+LLM裁决) │ 熔断状态机 │ 版本热替换  │
├────────────────────────────────────────────────────────────┤
│ 核心层  Generator(四层校验+自修正) │ AST Guard │ Executor   │
├────────────────────────────────────────────────────────────┤
│ 存储层  VectorStore(Chroma/numpy) │ 文件系统 skills/<n>/v{n}│
└────────────────────────────────────────────────────────────┘
```

- **接入层**：`api.py`（HTTP）与 `__main__.py`（CLI）共用同一个 `AutoSkillService`；`agent.py` 把注册表里的 active 技能实时编译成 function-calling 工具列表
- **调度层**：`router.py` 决定"召回 or 生成"；`registry.py` 维护技能元数据、熔断计数与版本历史，磁盘 `skill.json` 是唯一事实源
- **核心层**：`generator.py` 串联 LLM 生成与四层校验；`ast_guard.py` 是静态安全线；`executor/` 把"怎么跑"抽象成接口（local/docker 可插拔）
- **存储层**：`vectorstore.py`（Chroma cosine，本地 numpy 兜底）+ 技能文件系统（版本化目录）

## 2. 全链路时序

```
ensure(需求)
 ├─ Router.route
 │    embed(需求) ─► Chroma top-3 (where status=active)
 │    └─ LLM 裁决: {"decision": "use"|"none", "skill", "params", "reason"}
 │
 ├─[命中] validate_params(预校验)
 │    ├─ 不合法 ─► LLM 参数修复(×1) ─► 仍不合法 ─► 显式报错(不计熔断)
 │    └─ 合法 ─► Executor.execute ─► ok: record_success / 失败: record_failure
 │                                     └─ 转入生成路径(自修复触发点)
 │
 └─[未命中] 隔离技能检测(top-k 内 quarantined 且 sim≥下限 → 同名升级)
      Generator.generate (首试 + ≤3 轮自修正)
        ① JSON 解析/字段校验  ② compile 语法  ③ check_contract(run 入口)
        ④ check_code(AST 白名单/黑名单/dunder)  ⑤ 沙箱跑 LLM 自测用例
      ├─ guard 违规 ─► 拒绝(能力边界，无豁免通道)
      └─ 通过 ─► Registry.register(v1 新建 / v(n+1) 热替换)
              ─► 向量入库 upsert ─► 参数提取(修复×1) ─► 执行 ─► 返回
```

## 3. 技能生命周期（熔断状态机）

```
              register(v1)
   （不存在）────────────► active ◄──── record_success（重置计数）
                              │  ▲
                  连续失败 3 次│  │ 同名 v2 注册（热替换 current_version）
                              ▼  │
                         quarantined
                              │  路由排除(store 元数据同步)、直接调用显式拒绝
                              └── 同类需求 ensure ─► 触发同名修复 v2
```

- 熔断只统计**真实执行失败**（协议 ok=false / 超时 / runner 崩溃）；参数预校验失败是调用方错误，不计入
- 隔离触发时同步更新向量库元数据，路由立即排除，无需重启
- `skill.json.history` 保留全部版本引用，满足"上一稳定版本可回滚"

## 4. 关键设计取舍（面试重点）

### 4.1 禁网 vs HTTP 类技能

MVP 场景与安全模型必须自洽：沙箱策略是"禁网 + 只读 + 资源限制"，那么场景定位就必须砍掉 HTTP 类技能。两者不能同时出现在同一份设计里。
本项目的选择：**MVP 只做纯计算/格式转换技能**（白名单 22 个模块全部无 IO 能力），把"联网技能"划为 P1——方案是 egress 白名单代理（所有出站流量经代理白名单校验），而不是简单放开网络。这样安全叙事是连续的：`禁网沙箱 → 代理白名单沙箱`，而不是"禁网 → 禁网但偷偷能联网"。
（无 Docker 的 dev 环境下，静态层是唯一安全机制，更不允许出现"能联网但没隔离"的中间态。）

### 4.2 LLM 终审裁决 vs 纯相似度阈值

"命中已有技能还是生成新技能"是全系统最危险的分叉点：**错误命中是静默失败**——调了个不相关技能、返回看似成功实则错误的结果，比"重复生成"（无害）危险得多。
纯余弦阈值有两个结构性问题：阈值随技能数量增长需要持续调参；本地/embedding 模型对中文短句的区分度有限（实测本地哈希 embedding 下同义改述的绝对相似度只有 0.12~0.32，固定阈值根本不可靠）。
本项目的选择：**向量只做 top-3 粗召回，语义判断交给 LLM 裁决**——一次额外 LLM 调用（约 1s、约千元级 token）换来：命中决策、参数抽取、拒绝理由三者同时完成。技能规模到千级时，裁决成本可以通过"先标签粗筛再裁决"摊薄（见 §6）。

### 4.3 单测同源问题

实现代码和自测用例都出自同一个 LLM，"测试通过"不构成正确性证明——同源的幻觉会同时污染两者。
缓解措施（三层）：
1. **判分隔离**：验收与评测的期望值全部**人工预写、冻结**（`eval/evalset.json`），与 LLM 自生成的 `tests.json` 完全独立；LLM 自测只是"质量门禁"，不是正确性保证
2. **需求约束**：评测集的需求文本内嵌精确规则与示例（含边界），压缩歧义空间
3. **分层防御**：正确性最终由"沙箱执行 + 人工期望值比对"兜底，测试同源导致的漏判会被评测如实计入失败率

### 4.4 热加载 = 子进程现起，不用 importlib

既然技能本来就跑在独立子进程里，每次调用 spawn 新进程、读最新 `v{current}/impl.py`，**天然就是热加载**：注册表只存元数据与文件路径，主进程从不 import 技能代码。
带来的简化：importlib 的模块缓存污染、reload 状态残留、依赖冲突全部不存在；"回滚"退化为把 `current_version` 指回旧目录；进程隔离同时是行为隔离。importlib 进程内快路径只在未来做延迟优化时才值得引入（列为非目标）。

## 5. 安全模型

| 层 | 机制 | 边界 |
|----|------|------|
| 静态层 | AST 解析 impl：import 白名单（22 模块）、builtin 黑名单（eval/exec/open/...）、双下划线属性/名称封禁、相对导入封禁 | 主进程内即可拦截，无 Docker 环境下是唯一防线，故从严、无豁免 |
| 运行时层 | `python -I` 子进程（忽略 PYTHON* 环境变量）、stdin/stdout JSON 协议、超时杀整棵进程树、技能内 print 重定向隔离 | dev-only：**行为隔离，不是安全边界** |
| 生产层 | DockerExecutor（P1）：`--network none --read-only --memory 128m --pids-limit 64 --no-new-privileges` | 接口与配置项已就绪，同一评测脚本可双后端复跑 |
| 工程层 | 熔断隔离、显式错误协议（禁止静默失败）、注入需求必须被拒绝且不产生新技能 | 评测 C 组以 100% 拦截为门槛 |

## 6. 扩容路线（技能到 1000 个怎么办）

1. **标签粗筛**：生成时强制打标签，路由先按标签集合缩小候选域（千 → 数十）
2. **向量分片 + 常驻索引**：按域分 collection；embedding 换 provider 模型（配置即切换）
3. **裁决降级路径**：高频需求缓存（需求向量 → 技能映射的 LRU），命中免裁决
4. **治理**：相似度去重入库、版本灰度（新版本影子执行对比后替换）、熔断自动回滚到上一稳定版本
5. **评测即资产**：`evalset.json` 冻结期望值，任何架构变更复跑同一评测，回归可比
