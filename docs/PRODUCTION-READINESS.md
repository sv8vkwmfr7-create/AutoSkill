# 工程级落地自评报告（PRODUCTION READINESS）

> 评估日期：2026-11-18 · 版本 v1.1.0 · 全部证据来自本仓库可复现的实测
> 结论先行：**核心链路达到"单机工程可用"，生产容器化路径已完备（DockerExecutor 实装），距离"大规模多租户产品"还有明确列出的边界项**。

## 〇、真实故障演练（评估期间自然发生）

评测中途 DeepSeek 账户余额耗尽（HTTP 402）：系统行为完全符合工程要求——每个失败**显式报错**（错误信息含供应商原始错误码）、静默失败保持 0、无脏数据写入。切换 provider 仅修改 `.env`（换 TokenHub + glm-5.3-flash，零代码改动），复跑评测即全绿。**供应商可移植性与故障显式化经真实事故验证。**

## 一、评估方法

以工程级产品的八个维度逐项实测：功能完整性、可靠性、并发安全、安全隔离、可观测性、可部署性、可维护性、性能。每项证据均可通过仓库内命令复现，不接受"应该可以"。

### 2. 可靠性 ✅

- **失败显式化**：静默失败数 = 0（评测硬门槛）；所有失败带结构化 error 与归因（parse/contract/guard/sandbox）
- **供应商故障韧性**：LLM 余额耗尽（402）等供应商故障显式透传、零静默失败（评测期间真实发生并验证）
- **熔断状态机**：连续失败计数线程安全（并发 6 线程实测计数准确，`test_concurrent_call_breaker_consistent`）
- **降级硬化**：路由基础设施故障自动降级到生成路径（`_safe_route` 捕获一切路由异常）；LLM 网络/截断失败有重试与修复回喂
- **崩溃恢复**：进程重启自动对账（磁盘为唯一事实源）；向量库损坏可删除后全量重建

### 3. 并发安全 ✅（本轮新增）

- 全局生成锁 + 获锁后二次路由：3 线程并发 ensure 同一意图 → **只生成一次**（`test_concurrent_ensure_generates_once`）
- 召回失败复核跳过：同轮 ensure 不重复执行已失败的坏技能（skip 集）
- 注册表/熔断计数/事件日志均有锁；向量库本地实现带锁、Chroma 按官方线程语义使用
- 已知边界：FastAPI 同步端点在线程池中执行，生成路径串行化（单机规模合理；水平扩展属边界项）

### 4. 安全隔离 ✅（五层纵深，边界如实声明）

- 五层：AST 静态 → 受限内建命名空间 → PEP 578 审计沙箱 → 内存看门狗/Job Object → Docker 容器（详见 ARCHITECTURE §5，每层保证互不依赖，含攻击演示）
- 实测：别名攻击/动态 import/文件写入/越界读取/内存炸弹全部被拒（`test_security_hardening.py` 15 用例）
- **边界**：local 后端为用户态行为隔离（dev-only）；内核级隔离需启用已实装的 DockerExecutor——生产部署手册（DEPLOY.md）默认推荐容器后端

### 5. 可观测性 ✅（本轮新增）

- 事件审计轨迹：`ensure`/`call`/`rebuild` 全量落 `data/events.jsonl`（时间戳/路径/技能/耗时/成败），`GET /events` 与 CLI 可查
- `/health`：组件级状态（executor/embedding/store/llm/重建报告）
- 结构化日志（logging）+ 结构化错误协议（禁止裸栈外泄）

### 6. 可部署性 ✅（本轮新增）

- `pyproject.toml`：标准打包 + `autoskill` console 入口；`pip install -e .` 验证
- `Dockerfile`：构建期跑离线测试套件（测试不过 = 构建失败），服务一键容器化
- `.github/workflows/ci.yml`：push/PR 自动在 windows-latest + Python 3.14 跑全部测试
- `docs/DEPLOY.md`：两种拓扑（直跑 / Docker 沙箱）、systemd 单元、Nginx 前置、备份与恢复手册
- 配置：`.env` + 环境变量双层；**LLM 配置缺失启动即失败**并给出可读指引

### 7. 可维护性 ✅

- 测试：**94 项 pytest 全过**、全离线可复现（含并发、事件日志、API、安全加固用例）；CI（windows-latest + Python 3.14）自动执行
- 冻结评测集（35 条人工期望值）作为回归基线：任何改动 `python -m autoskill eval` 一键对账；已跨两个供应商复跑验证
- 文档：README（5 分钟复现）/ ARCHITECTURE（含五层安全模型与三个 trade-off）/ qa（12 条）/ DEMO（现场命令）/ DEPLOY（部署运维）/ PRODUCTION-READINESS（本文）
- 代码分层清晰：路由/生成/注册表/执行器/存储互相通过窄接口耦合，执行器可插拔（local/docker），LLM/Embedding/向量库均可配置切换

### 8. 性能 ✅（单机规模）

- 实测（deepseek-flash）：召回均值 ~1.2s（SLA ≤10s）、生成均值 ~8s（SLA ≤60s）、技能执行 0.15~0.25s
- 资源围栏：256MB 内存/32 进程/10s 超时，敌意负载不影响主进程

## 三、结论与边界

**结论：AutoSkill 当前版本是一个功能完整、可靠性有实测背书、安全有五层纵深、部署路径完备的单机工程可用系统。** 作为"完整可用的工程级落地产品"成立的前提与边界如下：

| 已达到 | 明确的剩余边界（非缺陷，是有意的范围决策） |
|--------|--------------------------------------------|
| 单机/单租户生产部署（直跑或 Docker 沙箱） | 多实例水平扩展（生成锁为进程内锁；跨实例需外置协调） |
| 五层沙箱 + 容器级隔离选项 | 内核级隔离依赖宿主安装 Docker |
| 事件审计 + 健康检查 | 分布式追踪/指标面板（可接 Prometheus，未做） |
| CI + 冻结评测回归 | 多租户权限、技能市场、前端面板（验收文档明列非目标） |
| 中文为主的评测与召回 | 英文等更多语言的 embedding 质量（可切 provider embedding） |

边界项都有明确的扩容路线（ARCHITECTURE §6），且**不影响当前形态作为单机工程产品的完整性**——它们是规模化的下一步，而不是可用性的缺口。
